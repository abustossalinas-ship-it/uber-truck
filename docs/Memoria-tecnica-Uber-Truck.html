Resumen ejecutivo del stack

Embarcadores y transportistas publican carga y capacidad ociosa vía web (public/). Un backend Node.js 20 + Express 4 expone REST con JWT, persiste en Supabase (PostgreSQL), gestiona emparejamientos, chat, notificaciones, cancelación (acuerdo mutuo / multas sugeridas) y resumen de cuenta. Despliegue en Railway; código en GitHub. Fase piloto previa: concierge (WhatsApp + Airtable) sin código.

Principio de producto

Validar match carga–camión y take rate 12–15% antes de pagos integrados, app nativa o pricing dinámico completo.

Parte II — Stack tecnológico por capas

Numeración de abajo hacia arriba y hacia el exterior (referencia en incidentes y actas).

Capa 01 — Node.js

Rol: runtime del servidor (src/server.js). Engines: ≥ 20. Problemas: puerto ocupado, versión distinta a prod → alinear Railway y package.json.

Capa 02 — Express.js

Rol: HTTP, JSON, estáticos public/, documentación /docs/, rutas /api/*, /health. Archivo: src/app.js.

Capa 03 — API REST

Rol: marketplace — ofertas, cargas, matches, auth, comms, cuenta. Auth: JWT en rutas protegidas. Rutas en src/routes/.

Capa 04 — Supabase (PostgreSQL)

Rol: persistencia; migraciones en supabase/migrations/. Proyecto prod: ljinhegtywixtbzjgjfn. Service role solo en servidor.

Capa 05 — Autenticación (JWT + bcrypt)

Rol: registro/login; tabla users; roles shipper / carrier. Sin sesión → sin notificaciones ni cuenta personalizada.

Capa 06 — Lógica de dominio

Rol: src/lib/ — match, cancelación (match-cancel-reasons.js), ledger multas (penalty-ledger.js), repositorio.

Capa 07 — Servicios

Rol: src/services/ — Supabase client, comms, integraciones futuras (mapas, pagos).

Capa 08 — Frontend web (SPA ligera)

Rol: public/index.html, app.js, auth-ui.js, comms-ui.js, penalties-ui.js, theme.css. Marca: naranja #F26522.

Capa 09 — Canal concierge (fase 1)

Rol: WhatsApp Business + Airtable — match manual sin código; validación antes de escalar digital.

Capa 10 — Railway

Rol: hosting, variables de entorno, healthcheck /health, deploy desde GitHub main.

Capa 11 — Git y GitHub

Rol: versionado; nunca commitear .env. Workflow CI: validación (deploy vía integración Railway).

Capa 12 — Documentación HTML

Rol: memoria viva, Gantt y próximos pasos en un solo HTML; export Word vía html-to-docx. Hub: /docs/index.html.

Reglas de negocio MVP

  • Match: corredor origen–destino, cubicación, tipo de carga compatible; sugerencias automáticas en UI.
  • Cancelación: catálogo de motivos; multas sugeridas (sin cobro automático); acuerdo mutuo requiere confirmación de ambas partes.
  • Plazo multa: 7 días; banco obligatorio antes de «generar cargo» (fase 2.10).
  • Comisión: take rate 12–15% sobre flete acordado.

Seguridad y cumplimiento

  • Secretos en .env; RLS Supabase por usuario cuando aplique.
  • Ley 19.628 (Chile): minimizar PII en logs.
  • Términos y seguro de carga antes de piloto con cobro real.
